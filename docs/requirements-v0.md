# 한글 폰트 메이커 — 요구사항 초안 v0

## 1. 제품 한 줄 정의

일반 사용자가 자모를 직접 그려 자신만의 한글 폰트를 만들고, 게임과 개인 창작물에 사용할 수 있는 폰트 파일로 내보내는 도구.

## 2. 문제와 기회

현대 한글 완성형은 11,172자다. 모든 글자를 하나씩 그리는 방식은 개인 창작자에게 지나치게 많은 시간과 전문 지식을 요구한다.

이 제품은 사용자가 직접 그린 초성·중성·종성 부품과 조합 규칙을 이용해 완성형 음절을 자동 생성한다. 사용자는 모든 음절을 제작하는 대신, 핵심 자모 형태를 그린 뒤 결과를 보며 필요한 글자만 보정한다.

## 3. 목표 사용자

### 주요 사용자

- 자신이 만든 게임에 어울리는 독자적인 한글 폰트를 쓰고 싶은 인디 게임 개발자
- 영상, 웹툰, 굿즈, 개인 웹사이트 등 창작물에 쓸 폰트를 만들고 싶은 일반 사용자
- 손글씨 또는 픽셀 스타일의 글꼴을 만들어 보고 싶은 학생·취미 창작자

### 사용자의 특징

- 폰트 편집기나 글꼴 형식에 대한 전문 지식이 없다.
- 원하는 분위기와 사용처는 알지만, 자모 조합 규칙은 모른다.
- 짧은 시간 안에 눈에 보이는 결과를 확인하고 싶다.
- 필요하면 일부 글자를 직접 고치고 싶지만, 11,172자를 편집하고 싶지는 않다.

## 4. 제품 원칙

1. **직접 그리기 중심**: 기본 폰트를 단순 변형하는 도구가 아니라, 사용자의 선과 형태에서 출발한다.
2. **복잡성은 엔진이 담당**: 자모 유형, 조합 규칙, 유니코드 범위 같은 전문 개념은 기본 화면에서 드러내지 않는다.
3. **즉시 확인**: 사용자가 그리거나 수정할 때마다 글자와 실제 문장 결과를 빠르게 보여 준다.
4. **수정 가능성**: 자동 결과가 어색할 때, 사용자가 해당 자모 또는 특정 음절을 쉽게 고칠 수 있어야 한다.
5. **게임 사용성**: 작은 화면에서도 읽기 쉬운지 확인하고, 실제 게임 프로젝트에 넣을 수 있는 결과물을 만든다.

## 5. MVP 범위

### 5.1 필수 기능

#### A. 프로젝트 만들기

- 새 폰트 프로젝트를 만들고 이름, 기본 캔버스 크기, 사용 목적을 정한다.
- 첫 버전의 스타일은 `픽셀 폰트`와 `자유형 선 그리기` 중 선택한다.
- 사용 목적은 미리보기와 내보내기 안내에만 활용하며, 조합 결과를 제한하지 않는다.

#### B. 자모 직접 그리기

- 사용자는 격자가 있는 캔버스에 초성·중성·종성의 기본 형태를 직접 그린다.
- 픽셀 모드에서는 칸을 칠하고 지울 수 있다.
- 자유형 모드에서는 선을 그리고, 지우고, 이동·확대·축소할 수 있다.
- 획 두께, 기준선, 중앙선, 안전 여백을 시각적으로 제공한다.
- 어떤 자모를 먼저 그려야 하는지 단계별로 안내한다.

#### B-1. 작성 시트 사진 가져오기

- 사용자가 인쇄 또는 디지털 작성 시트의 정해진 칸에 자모를 그리고, 사진 또는 스캔본을 업로드할 수 있다.
- 시트의 모서리 기준 표식 또는 QR 코드를 이용해 시트 위치를 인식하고 원근·회전을 보정한다.
- 각 칸은 미리 지정된 자모와 배치형에 연결된다. 따라서 시스템은 그림의 자모를 추측하는 대신, 해당 칸의 그림을 지정된 자모로 가져온다.
- 업로드 결과를 칸별로 미리 보여 주고, 사용자가 잘못 인식되거나 잘린 칸을 수정·재촬영할 수 있어야 한다.

#### B-2. 그림 전처리와 정규화

- 사진에서 배경, 종이 색, 그림자, 시트 격자선을 줄이고 사용자가 그린 획을 추출한다.
- 각 칸의 획 영역을 찾아 불필요한 빈 공간을 자르되, 가로세로 비율은 유지한다.
- 획은 자모 유형별 목표 작업 영역 안에 정해진 최소 여백을 두고 확대 또는 축소한다.
- 단순히 획의 중심을 캔버스 중앙으로 맞추지 않는다. 초성·중성·종성별 기준점(anchor), 기준선, 종성 공간을 사용하여 조합에 필요한 위치 정보를 보존한다.
- 정규화 전 원본과 정규화 후 결과를 모두 보관해 사용자가 되돌리거나 보정할 수 있어야 한다.

#### C. 한글 자동 조합

- 초성 19개, 중성 21개, 종성 27개 및 종성 없음의 조합을 이용해 현대 한글 11,172자를 생성한다.
- 중성의 배치 유형과 종성 유무에 따라 서로 다른 초성·중성·종성 형태를 선택한다.
- 종성이 있는 음절은 초성·중성 영역을 조정하고 종성 공간을 확보한다.
- 글자 겹침 또는 캔버스 밖으로 나가는 결과를 감지해 사용자에게 표시한다.

#### D. 결과 미리보기 및 보정

- `가나다`, 자주 쓰는 문장, 사용자가 입력한 게임 대사로 결과를 미리 본다.
- 한 글자를 선택하면 해당 글자의 초성·중성·종성과 배치 정보를 확인할 수 있다.
- 사용자는 자모 원본을 수정하거나, 특정 음절의 위치·크기를 예외적으로 보정할 수 있다.
- 예외 보정은 해당 음절에만 적용되는지, 같은 조합 유형 전체에 적용되는지 선택할 수 있다.

#### E. 내보내기

- 완성형 한글을 포함한 설치 가능한 폰트 파일을 내보낸다. 첫 번째 목표 형식은 TTF다.
- 게임용으로 사용할 수 있도록 권장 크기와 렌더링 주의사항을 안내한다.
- 폰트 이름, 제작자, 버전, 사용 라이선스 문구를 설정할 수 있다.

### 5.2 MVP에서 제외하는 기능

- 한자 및 모든 외국어 문자 세트의 완전한 지원
- 전문가용 Bézier 곡선 편집·힌팅·커닝 편집
- 가변 폰트 생성
- AI가 사용자의 그림체를 자동 완성하는 기능
- 여러 사람이 동시에 편집하는 협업 기능
- 상업적 사용 가능성을 자동으로 보장하거나 타인의 폰트 저작권을 판정하는 기능

## 6. 핵심 사용자 흐름

1. 사용자가 “새 폰트 만들기”를 누르고 픽셀 또는 자유형 방식을 고른다.
2. 도구가 `ㄱ`, `ㅏ` 등 필요한 자모와 변형 형태를 순서대로 안내한다.
3. 사용자가 자모를 그릴 때마다 `가`, `각`, `고`, `광` 등 대표 조합 결과를 바로 보여 준다.
4. 사용자가 문장 미리보기에서 이상한 글자를 발견하면 해당 글자를 선택해 자모 또는 배치를 보정한다.
5. 사용자가 전체 한글을 생성하고, 경고 목록을 검토한다.
6. 사용자가 폰트 정보와 라이선스를 입력한 뒤 TTF 파일로 내보낸다.
7. 사용자가 게임 엔진 또는 운영체제에 설치해 실제 사용한다.

## 7. 수용 기준 (MVP 성공 조건)

- 폰트 제작 경험이 없는 사용자가 안내를 따라 최소한 `가나다라마바사`와 자신이 입력한 한글 문장을 생성할 수 있다.
- 사용자가 직접 만든 자모를 바탕으로 현대 한글 11,172자를 생성할 수 있다.
- `가`, `각`, `고`, `공`, `과`, `광`, `귀`, `귁`처럼 대표적인 모음·종성 조합에서 구성 요소가 의도치 않게 겹치지 않는다.
- 사용자가 어색한 특정 음절 하나를 수정하고 결과를 다시 내보낼 수 있다.
- 내보낸 TTF가 일반 운영체제 또는 목표 게임 엔진에서 설치·표시된다.

## 8. 비기능 요구사항

- 일반적인 PC 환경에서 자모 수정 후 대표 미리보기가 1초 안에 갱신되어야 한다.
- 전체 11,172자 생성 과정의 진행 상태와 오류를 보여 주어야 한다.
- 자동 저장 또는 명확한 저장 상태 표시를 제공해야 한다.
- 프로젝트 파일을 다시 열어 자모, 조합 규칙, 예외 보정을 이어서 편집할 수 있어야 한다.
- 키보드와 마우스만으로 주요 편집 기능을 사용할 수 있어야 한다.

## 9. 기술·제품상 확인할 위험

- 사용자가 자모의 여러 배치형을 이해하지 못할 수 있다. → 화면에서는 “가로 모음용”, “세로 모음용”, “받침 있음”처럼 결과 중심 언어를 사용한다.
- 사용자가 그린 자모가 조합 시 충돌할 수 있다. → 사전 경고, 자동 여백 조절, 예외 보정 도구가 필요하다.
- 자유형 손글씨를 TTF 윤곽선으로 변환할 때 품질이 낮아질 수 있다. → MVP는 픽셀 방식부터 안정적으로 지원하는 방안을 검토한다.
- 폰트 파일 호환성과 라이선스 정보가 게임 배포에 영향을 줄 수 있다. → 실제 게임 엔진별 시험이 필요하다.
- 사진 전처리 과정에서 획의 위치와 비율을 모두 균일하게 만들면, 자모의 개성은 유지되더라도 한글 조합에 필요한 여백이 사라질 수 있다. → 글자 인식용 중심 정렬이 아니라 자모별 기준점 기반 정렬을 사용한다.

## 10. 다음 결정이 필요한 항목

1. 첫 번째 MVP의 제작 방식은 픽셀 폰트만 지원할지, 자유형 선 그리기도 함께 지원할지
2. 앱 형태는 웹 앱, 데스크톱 앱 중 무엇으로 시작할지
3. 첫 번째 검증 대상 게임 엔진은 무엇인지 (예: Unity, Godot, Unreal)
4. 사용자가 그려야 하는 자모 변형형을 어떻게 안내하고 최소화할지
5. TTF 외에 게임용 비트맵 폰트 형식을 첫 버전에 포함할지
